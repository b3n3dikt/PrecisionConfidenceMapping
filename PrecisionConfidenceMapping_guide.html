1. What is PCM?

Precision Confidence Mapping answers the question: "How confidently can we assign each brain vertex to a functional network, given a finite amount of fMRI data?"

It works by:

  1. Taking a subject's fMRI time series and shuffling the timepoints N times (bootstrap)
  2. Running community detection on each shuffled version
  3. Tallying, across all N permutations, how often each vertex was assigned to each network

The result is a probability/confidence map per network: vertices with values near 1.0 have stable, reliable assignments; vertices near 0.5 are ambiguous. A mode map shows the single most common assignment at each vertex.

PrecisionConfidenceMapping supports two community detection algorithms, selected with the METHOD parameter:

METHODAlgorithmBest for
matlab_tm default MATLAB template matching — correlates each vertex's time series against network seed maps; assigns to highest-correlation network Fast runs, well-validated results, standard PCM output
reprotm Python template matching (ReproTM, Godfrey et al.) — builds a z-scored dconn per permutation, winner-take-all matches each greyordinate to a network seed map, then min-size cluster cleanup Reproducible Python TM, optional SCAN refinement

Both methods write output to the same .conc format (each perm published as *_recolored.dscalar.nii), so the figure-making code (probability maps, mode maps, surface images) works identically for both. A full list of what you need installed is in Section 7 — Requirements.

⚠️ In-development notice: matlab_tm is the original PCM method — extensively tested and the basis of published results. reprotm is a newer addition with less cluster-testing history; treat its outputs as provisional and inspect them carefully before relying on them.

2. Setup

PrecisionConfidenceMapping bundles almost everything it needs: network templates and figure utilities all ship inside the folder. One piece is fetched separately instead of vendored for licensing reasons — matlab_tm's core code (Section 2b, one-time, required since matlab_tm is the default method) — and ReproTM's core code is fetched too, since PCM doesn't vendor a copy of that either (Section 2c, one-time, optional — only if you use METHOD=reprotm). Both are a single script; neither requires an account or manual download. Beyond that, setup is mostly about telling PCM where to run (your cluster account/partitions) and what to run on (your data).

2a. Get the code — you usually don't need the whole folder

If your group already maintains a shared install of PrecisionConfidenceMapping on the server, you can point to it directly — there is no need to copy the whole package. For example, on MSI:

/projects/standard/faird/shared/code/internal/analytics/PrecisionConfidenceMapping/

Pick the option that matches what you need:

Your situationWhat to do
Using the defaults + optional flags (most users) Don't copy anything heavy. Either run the shared run_PCM.sh directly with flags, or copy just run_PCM.sh and cluster.conf into your study folder and edit those. PCM finds the rest of the package automatically.
Editing run_PCM.sh / cluster.conf settings Copy run_PCM.sh and cluster.conf into your study directory and edit them there. PCM prioritizes the copies in your run directory over the ones in the base install, so your edits never touch the shared package.
Editing the deeper pipeline code (rare) Clone the whole repo so you have your own version to modify. Directly on a login node (or anywhere with internet access):
git clone https://github.com/b3n3dikt/PrecisionConfidenceMapping.git
No internet on the cluster at all? Clone locally and copy it over instead:
scp -r PrecisionConfidenceMapping/ yourserver:/path/to/destination/
💡 If you copy run_PCM.sh out of the package, set PCM_DIR at the top of it to the base install path so it can find the bundled code: 
PCM_DIR="/projects/.../PrecisionConfidenceMapping"

2b. Fetch matlab_tm required — matlab_tm is the default method

METHOD="matlab_tm" is PCM's default, but its core code is not bundled in this package. template_matching_RH.m (R. Hermosillo / UMN) is licensed for non-profit/research use only, with no redistribution without approval — so instead of vendoring a copy, PCM fetches it directly from its public home at setup time. Run this once, before your first METHOD=matlab_tm run:

bash code/setup_matlab_tm.sh

This clones DCAN-Labs/compare_matrices_to_assign_networks (github.com/DCAN-Labs/compare_matrices_to_assign_networks) into deps/matlab_tm/ at a pinned commit, then applies PCM's patch on top — fixes a crash caused by the bundled cifti-matlab library returning a different data type than the original code expected, a probable pre-existing bug in a threshold-tiling calculation, and strips a couple of hardcoded server paths. See patches/template_matching_RH.patch for the full explanation of each change, and its accompanying LICENSE.txt (fetched alongside it into deps/matlab_tm/) for the terms governing that code.

⚠️ Run this on a login node or your own workstation — not inside a SLURM job. Compute nodes are frequently firewalled off from the internet on HPC clusters, so this can't happen automatically mid-pipeline. If you forget this step, run_PCM.sh fails fast with a reminder before submitting any jobs, rather than partway through a permutation.
💡 Safe to re-run — does nothing if deps/matlab_tm/ is already set up correctly. Pass --force to wipe it and re-fetch from scratch. Only needed for METHOD=matlab_tm; skip this if you only ever use reprotm (Section 2c, its own setup step).

2c. Fetch ReproTM optional — only for METHOD=reprotm

Only needed if you plan to use METHOD=reprotm. Unlike matlab_tm, ReproTM (Godfrey et al.) has no license restricting redistribution — it's just missing a LICENSE file — so this step offers a choice of two modes instead of matlab_tm's one:

bash code/setup_reprotm.sh              # --pinned (default): known-good commit,
                                         # compatibility patches applied
bash code/setup_reprotm.sh --latest     # current upstream HEAD instead

Both clone into deps/reprotm_fetched/, picked up automatically — no cluster.conf edit needed unless you want to override it (Section 2d).

ModeWhat it doesTrade-off
--pinned defaultClones a specific commit PCM has verified works; applies known compatibility fixes unconditionally.Guaranteed to work — immune to Kate restructuring the codebase later. Won't pick up her improvements automatically.
--latestClones current upstream HEAD. Each fix is tried first and only applied if still needed — anything Kate's already fixed upstream is skipped automatically, with a message.Gets her improvements as she ships them. If she's changed a lot since the pin, something might not work — you'd fix it by hand (see deps/reprotm/COMPATIBILITY_NOTES.md).
💡 Safe to re-run in the same mode — does nothing if already set up. Switching modes (or an unexpected existing state) requires --force to wipe and re-fetch. Prefer to manage your own ReproTM install instead of using this script at all? That still works — see deps/reprotm/README.md and set REPROTM_DIR yourself in cluster.conf (Section 2d), which overrides the fetched default.

2d. Configure cluster.conf most important step

Edit cluster.conf with your cluster's account, partitions, and module names. PCM reads the copy in your run directory first, then falls back to the base install — so keep a copy per study and you'll never edit the shared one:

SLURM_PARTITION="msismall,ag2tb"   # check: sinfo -s
SLURM_ACCOUNT="yourgroup"           # check: sacctmgr show user
MATLAB_MODULE="matlab/R2019a"       # check: module avail matlab
WORKBENCH_MODULE="workbench"        # check: module avail workbench

# Only for METHOD=reprotm — OPTIONAL override. Leave commented out to use the
# copy `bash code/setup_reprotm.sh` fetches for you (Section 2c). Only set this
# if you want your own separately managed ReproTM install instead:
# REPROTM_DIR="/path/to/your/ReproTM"

# Also only for METHOD=reprotm — a python that has nibabel + scipy + numpy.
# The cluster's default python3 usually lacks nibabel; point this at a conda env
# (call its python by absolute path — batch jobs don't source your ~/.bashrc):
REPROTM_PYTHON="/projects/.../miniconda3/mini3/bin/python"

# SLURM resource sizing (per-method + auxiliary jobs) — optional, sensible
# defaults ship already. See Section 4l for the full list of variables.
MATLABTM_MEM="128gb"   REPROTM_MEM="200gb"
💡 The bundled scripts and templates ship with the package — you do not need to verify they are present. The thing that lives outside the package, and therefore needs configuring here, is REPROTM_DIR/REPROTM_PYTHON (reprotm). Unlike matlab_tm's fetch, PCM does not vendor a copy of ReproTM at all — see Section 4d and deps/reprotm/README.md. SLURM resource sizing (Section 4l) also lives here now — most users won't need to touch it, since the shipped defaults already match what run_PCM.sh used to hardcode.

2e. Set your inputs — in run_PCM.sh or as flags

You can provide inputs either by editing the USER SETTINGS block of run_PCM.sh, or by passing them as command-line flags (handy for one-off runs). Flags override the file.

# ── In run_PCM.sh USER SETTINGS, or as --flags ──
dtseries="/path/to/sub-001_ses-01_task-rest_bold.dtseries.nii"
motion_file="/path/to/motion.mat"    # .mat | .hdf5 (auto-converted) | .txt (0/1 mask)
surf_L="/path/to/hemi-L_midthickness.surf.gii"
surf_R="/path/to/hemi-R_midthickness.surf.gii"
BASEDIR="/path/to/outputs/"          # output ROOT only — see note below

METHOD="matlab_tm"                   # matlab_tm | reprotm
💡 SUB, SES, and TASK are auto-parsed from the dtseries filename when it follows BIDS naming (e.g. sub-001_ses-01_task-rest_bold.dtseries.nii). Only set them explicitly (file or --sub/--ses/--task) if your filename is not BIDS-formatted.
⚠️ Do not put sub/ses in BASEDIR. It is just the output root — PCM appends sub-XXX/ses-YYY/task-… itself. Use --basedir /path/to/outputs/, not .../outputs/sub-001/ses-01.

3. Running PCM

Every run needs the five required inputs (dtseries, motion, surf-L, surf-R, basedir) — whether set in run_PCM.sh or passed as flags. The method and other options are layered on top.

Standard run (full dataset, matlab_tm)

💡 First time using METHOD=matlab_tm (the default)? Run bash code/setup_matlab_tm.sh once first — see Section 2b. run_PCM.sh will remind you if you forget. 
# If the USER SETTINGS in run_PCM.sh are filled in:
sbatch run_PCM.sh

# Or pass everything as flags (BIDS dtseries → sub/ses/task auto-parsed):
sbatch run_PCM.sh \
    --dtseries /path/to/data/sub-001_ses-01_task-rest_bold.dtseries.nii \
    --motion   /path/to/data/motion.mat \
    --surf-l   /path/to/data/hemi-L_midthickness.surf.gii \
    --surf-r   /path/to/data/hemi-R_midthickness.surf.gii \
    --basedir  /path/to/outputs/

Run with ReproTM

💡 First time using METHOD=reprotm? Run bash code/setup_reprotm.sh once first — see Section 2c. run_PCM.sh will remind you if you forget. 
# Same required inputs — you cannot run --method reprotm by itself.
# --template defaults to the bundled ABCC seedmap; --template scan reuses the
# matlab_tm SCAN template (see Section 4j):
sbatch run_PCM.sh --method reprotm --template scan \
    --dtseries /path/to/data/sub-001_ses-01_task-rest_bold.dtseries.nii \
    --motion /path/to/data/motion.mat \
    --surf-l /path/to/data/hemi-L_midthickness.surf.gii \
    --surf-r /path/to/data/hemi-R_midthickness.surf.gii \
    --basedir /path/to/outputs/
⚠️ METHOD=reprotm requires ReproTM (Godfrey et al.), which PCM does not bundle — run bash code/setup_reprotm.sh once (Section 2c), or set REPROTM_DIR in cluster.conf (Section 2d) to your own local install instead. run_PCM.sh checks this exists before submitting any jobs and errors immediately if it's missing or misconfigured.
💡 METHOD=reprotm also needs a Python with nibabel/scipy/numpy — set REPROTM_PYTHON in cluster.conf (Section 2d). A preflight check fails the job in seconds if it's misconfigured, before the ~40-min dconn build.

Add options on top of the required inputs

The examples below show only the option being added — the five required inputs still apply.

# Time truncation (see 4k):
sbatch run_PCM.sh ... --startmins 10                 # first 10 minutes
sbatch run_PCM.sh ... --startmins 10 --keepfrom end  # last 10 minutes
sbatch run_PCM.sh ... --startmins 5 --increment 5 --endmins 20  # 5,10,15,20

# Binary motion mask instead of FD (.txt of 0/1 per TR):
sbatch run_PCM.sh ... --motion /path/to/sub-001_custom_mask.txt

# Shuffle method (see 4h):
sbatch run_PCM.sh ... --shuffle bagging --shuffle-chunk-size 5

Get help & monitor

bash run_PCM.sh --help          # full flag list

squeue -u $USER                 # running jobs
# Logs live inside each task folder:
cat BASEDIR/sub-SUB/ses-SES/TASK_FOLDER/logs/orchestrator_*.out
cat BASEDIR/sub-SUB/ses-SES/TASK_FOLDER/logs/perm_*.out

Combined figures across methods / runs

# Default: combine ALL task-TASK_* folders for this subject:
bash run_PCM.sh --combined-figs \
    --basedir /path/to/outputs/ \
    --dtseries /path/to/data/sub-001_ses-01_task-rest_bold.dtseries.nii

# Include only specific folders (e.g. exclude test runs) and name the output:
bash run_PCM.sh --combined-figs \
    --basedir /path/to/outputs/ \
    --dtseries /path/to/data/sub-001_ses-01_task-rest_bold.dtseries.nii \
    --includefolder task-rest_method-matlabTM_tmpl-scan_sh-bootstrap \
    --includefolder task-rest_method-reproTM_tmpl-scan_sh-bootstrap \
    --combined-name matlabtm-reprotm     # → task-rest_combined_matlabtm-reprotm/

4. Parameter Reference

This section documents every input and setting in run_PCM.sh that controls how your PCM run behaves — the required inputs, the method, and all the optional knobs.

💡 How to set anything below: every parameter can be set two ways — as a variable in the USER SETTINGS block of run_PCM.sh (your standing default), or as a --flag on the command line (overrides the file, ideal for one-off changes). Tables show both the variable name and the flag where they differ.

These five must be provided every run — in USER SETTINGS or as flags.

Set METHOD in run_PCM.sh, or pass --method.

ValueAlgorithmNotes

4e. Shared dconn settings

Both methods build their dense connectivity matrix (dconn) via the same underlying tool (cifti_conn_matrix_for_wrapper_continous), so these settings apply regardless of METHOD:

ParameterDefaultDescription
SMOOTHING_KERNEL / --smoothing-kernel2.25Smoothing kernel (mm) applied to the dtseries before dconn computation. Set to 0 to skip.
FISHER_Z / --fisher-z1Fisher-z transform the correlations before the sectional z-scoring step. Set to 0 for plain Pearson r.
REMOVE_OUTLIERS / --remove-outliers1Standard-deviation-based outlier frame removal on top of FD-based motion censoring.

4f. Motion options

Set motion_file / --motion to your motion file. Three formats:

ExtensionFormatBehavior
.matDCAN FD formatUsed directly. FD threshold set by FD / --fd (default 0.2 mm).
.hdf5XCP-D formatAuto-converted to .mat once in run_PCM.sh before submission.
.txtBinary frame maskOne integer per line: 1 = keep, 0 = remove. Bypasses FD filtering. Line count must match TR count.
⚠️ A .txt motion mask and time truncation (--startmins) cannot be used together. Pre-truncate your data manually if you need both.

4g. Spatial noise interpolation

Runs MATLAB spatial noise interpolation on the dtseries before anything else (smoothing/dconn/shuffling all happen after). Applies to every method.

Variable / FlagDefaultDescription
intrp_noise / --interp-noise0 (off)Set to 1 to run interpolation. Unchanged default behavior if you don't pass this flag.

If a sibling <dtseries-basename>_spatially_interpolated.dtseries.nii already exists next to your --dtseries file, PCM reuses it instead of recomputing (only checked when --interp-noise 1 is set). If you leave --interp-noise unset and your dtseries filename doesn't end in that suffix, PCM prints an [INFO] hint suggesting --interp-noise 1 — it does not turn interpolation on automatically; that would silently change what runs for anyone not passing the flag.

⚠️ One thing cluster.conf can't cover: run_PCM.sh's own top-of-file #SBATCH partition/account (the very first job SLURM submits). ⚠️ The orchestrator job itself runs up to 48 hours while it monitors permutation jobs. If it dies, permutation jobs may still finish, but figures won't be generated automatically — just re-run the same command and PCM resumes from the completed perms.

4m. Combined figures

A lightweight mode that operates on existing permutation outputs without repeating the full pipeline.

--combined-figs (or COMBINED_FIGS=1)

Concatenates successful_perms.conc across task folders and submits one make_figs job to build confidence maps from the combined pool. Only --basedir is required (plus --sub/--ses/--task if not parseable from --dtseries). Re-runnable any time to incorporate new methods.

FlagDescription
(default)Combine all task-TASK_* folders for the subject.
--includefolder PATH (repeatable)Combine only these folders instead of auto-scanning. PATH may be an absolute path or just the task-folder name (resolved under sub-/ses-). Lets you exclude test runs without deleting them.
--combined-name NAMESuffix the output folder → task-TASK_combined_NAME (default: task-TASK_combined).

5. What happens when you run

Step 1 — run_PCM.sh (submitted by you)
Validates inputs and method, converts .hdf5 motion files if needed, calculates TR and scan duration. Then submits the orchestrator as a SLURM job.
↓
Step 2 — orchestrate_PCM.sh (long-running SLURM job, up to 48h)
Checks which permutations are already done. Submits one SLURM job per missing permutation. Polls SLURM every 60 seconds until all finish, then submits the figure job.
↓ × N (one per permutation, run in parallel)
Step 3 — run_permutation.sh (one per permutation)
METHOD=matlab_tm
Sets up /tmp workspace. Runs MATLAB shuffle on the time series. Runs template matching (which builds its own dconn internally via cifti_connectivity, then z-scores it). Copies *_recolored.dscalar.nii to BASEDIR and appends its path to the .conc.
METHOD=reprotm
Preflight-checks the Python. /tmp workspace → MATLAB shuffle → dconn prologue (smooth → cifti_connectivity → Zscore_dconn). Then pure Python:
  1. ReproTM_v1.0.0.py → network assignment
  2. minsize_v1.0.0.py → cluster cleanup
Copies output as *_recolored.dscalar.nii to BASEDIR and appends to the same .conc.
↓ (after all permutations finish)
Step 4 — make_figs.sh → TM_dscalar_compare_across_permutations.m
Reads all permutation outputs from the .conc file (works for both methods). Computes probability maps and the mode map, and generates surface/subcortical visualization images.
💡 Fault tolerance: the orchestrator re-checks for completed permutations before submitting — so re-running run_PCM.sh for the same subject only submits the perms that didn't finish last time.

7. Requirements

Almost everything PCM needs is bundled in the package. The only things you supply are a few cluster modules, your data, and (per method) one or two external pieces noted below.

DependencyHow loadedNotes
Operating system—Linux (developed and tested on MSI, a SLURM-based HPC cluster). Not designed for macOS or Windows — needs a SLURM scheduler, Linux builds of MATLAB/Workbench, and a per-permutation memory footprint well beyond a typical laptop regardless of OS (Section 4l).
SLURMSystem schedulerRequired. PCM submits one SLURM job per permutation.
MATLABmodule load matlabR2019a or later. Set MATLAB_MODULE in cluster.conf.
Workbench (wb_command)module load workbenchCIFTI operations and smoothing. Set WORKBENCH_MODULE.
Python 3System / module / condaPermutation status checks; ReproTM (see below).
fMRI data—From XCP-D, ABCD DCAN, or BICEPS. Need dtseries + motion + L/R surface .gii.

Bundled — nothing to download or verify: cifti-matlab, cifti_connectivity, figure utilities, and all network templates (including ReproTM's default template) ship inside deps/ and templates/.

Not bundled — you fetch these: both methods' core code is not vendored in this repo, but both are a single script away. METHOD=matlab_tm (the default) needs a one-time bash code/setup_matlab_tm.sh (Section 2b) — fetched from its public GitHub home at a pinned commit, patched automatically, no account needed. METHOD=reprotm needs bash code/setup_reprotm.sh (Section 2c) — same idea, but with a choice of --pinned (default, known-good) or --latest (current upstream, patches applied only if still needed) since ReproTM isn't license-restricted the way matlab_tm is. Neither is an oversight — see patches/template_matching_RH.patch and deps/reprotm/README.md for why each is fetched rather than vendored. Prefer to manage ReproTM yourself instead of using the fetch script? Set REPROTM_DIR in cluster.conf to override the fetched default (see deps/reprotm/README.md) — matlab_tm doesn't currently support this, since its whole point is fetching one specific, verified source.

Install time: cloning the repo and running the one-time setup script(s) (setup_matlab_tm.sh and/or setup_reprotm.sh) is typically a few minutes on a machine with ordinary internet access — mostly git clone plus fetching two small upstream method repositories; there's no compilation step. This hasn't been formally benchmarked — time a clean install before quoting a number in a publication.

The method-specific externals you configure (in cluster.conf):

ForWhat you provide
METHOD=matlab_tmNothing to configure — just run bash code/setup_matlab_tm.sh once (Section 2b) before your first run. run_PCM.sh checks it's been done before submitting jobs.
METHOD=reprotmRun bash code/setup_reprotm.sh once (Section 2c) — nothing to configure unless you want your own install instead (REPROTM_DIR). PCM checks it exists before submitting jobs. Also REPROTM_PYTHON — a python with nibabel/scipy/numpy (the default python3 usually lacks nibabel). A conda env's python by absolute path works well.

8. Troubleshooting

ProblemWhat to check
"Required inputs are missing"Ensure dtseries, motion_file, surf_L, surf_R, BASEDIR are all set (file or flags). bash run_PCM.sh --help lists everything.
"Could not parse SUB/SES/TASK"Filename isn't BIDS. Set --sub/--ses/--task (or the variables).
"motion file not found" / bad extensionMust be .mat, .hdf5, or .txt.
Permutation jobs fail immediatelyCheck TASK_DIR/logs/perm_*.out. Common: surface .gii not found, too little scratch (tmpspace), wrong MATLAB module in cluster.conf.
Figures not generatedThe figure job runs after all perms complete. If the orchestrator timed out (48h), just re-run run_PCM.sh — it skips completed perms and proceeds to figures.
"Index … exceeds array bounds" in the MATLAB shuffleWas a stale shuffle-order cache from a different truncation length; caches are now keyed by frame count. Re-run with the current code; delete any old BASEDIR/*_order_*.mat if needed.
[matlab_tm] "METHOD=matlab_tm requires template_matching_RH.m … which PCM does not bundle"Run bash code/setup_matlab_tm.sh once (Section 2b) — do this on a login node/workstation with internet access, not inside a SLURM job.
[reprotm] "METHOD=reprotm requires ReproTM … which PCM does not bundle"Run bash code/setup_reprotm.sh once (Section 2c) — same login-node/workstation caveat as matlab_tm above.
[reprotm] setup_reprotm.sh: "already exists (mode: …), but you asked for --…"You're switching between --pinned and --latest on an existing fetch. Add --force to wipe and re-fetch in the new mode.
[reprotm] "ModuleNotFoundError: nibabel"Point REPROTM_PYTHON at a python that has nibabel/scipy/numpy (conda env, absolute path). The preflight reports which import failed within seconds.
[reprotm] networks mislabeledFor a custom .mat, set REPROTM_NETWORKS to match the template's seed_matrix column order.
Wrong SLURM partition/accountEdit cluster.conf in your study directory. sinfo -s for partitions, sacctmgr show user for account.
Poor confidence maps (everything low)Check frames retained after motion censoring — too-strict FD or a short scan leaves too little data. Try a higher FD or verify the correct template.
